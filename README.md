# PVE UPS 管理

在单台家用 PVE 宿主机上安装和管理 `apcupsd`，通过 APC UPS 的 USB 连接监控供电状态，并在持续停电或电池余量不足时启动 PVE 正常关机。

项目提供简体中文终端菜单、命令行操作、可导出的配置和卸载恢复记录。菜单关闭后，监控和自动关机仍由系统中的 `apcupsd` 服务负责。

## 源码和验证状态

项目提供 `v0.1.0` 源码，当前通过 [GitHub 仓库](https://github.com/EluneAdore/pve-apcupsd-manager)的 `main` 分支发布，也可使用本地 tar 源码包部署。

真实 PVE 与 UPS 硬件验收待完成。当前开发环境不是连接 UPS 的真实 PVE，隔离测试通过不代表已经完成实机断电验收。正式使用前，请按[硬件验收说明](docs/硬件验收.md)验证 UPS 通信、来电取消计时和正常关机。

## 已确定的行为

| 项目 | 行为 |
| --- | --- |
| 监控方式 | 宿主机原生 `apcupsd`，使用发行版软件包和服务 |
| 默认停电等待 | 30 分钟，即 `TIMEOUT 1800` |
| 停电确认延迟 | `ONBATTERYDELAY 0`，实际检测存在 UPS 与服务的轮询间隔 |
| 计时中恢复市电 | 结束本次计时，取消尚未开始的关机 |
| 再次停电 | 从完整设定时长重新计时 |
| 新安装保护阈值 | 电量 5%、剩余续航 3 分钟 |
| 已有安装保护阈值 | 保留符合校验范围的原有值 |
| 电池保护 | 任一保护条件满足时可提前关机，UPS 自身的低电量信号也可能触发关机 |
| 已开始关机后恢复市电 | 继续完成停机 |
| 参数修改 | 每项校验、保存并应用，成功后显示实际值；失败时恢复旧配置文件；监控停止时保存后在下次启动生效 |

30 分钟是持续停电的等待上限，不保证电池可以供电 30 分钟。给虚拟机、容器及宿主机停止所需的时间留出足够电池余量。

参数生效可能需要重启 `apcupsd`。为防止重启清空当前计时，电池供电期间不允许修改参数、导入配置、升级软件或停止、重启监控。服务运行但通信状态未知时，也会阻止这些操作；查询和诊断仍可使用。

升级和重启存在短暂监控中断。工具在开始维护前确认市电，也会在软件索引更新后再次检查供电；维护瞬间发生的新停电仍无法保证无缝监控。配置应用后若通信失败，工具会恢复旧配置文件；供电无法确认时不会再次重启，应通过诊断核对当前实际运行值。

## 中文菜单

安装后的入口为：

```sh
pve-ups
```

主菜单示意如下，屏幕中的状态以当前实际读数为准：

```text
──────── PVE UPS 管理 ────────
软件：已安装       监控：运行中
供电：市电供电     电量：当前读数
关机倒计时：未启动

1. 查看 UPS 详细状态
2. 修改关机设置
3. 安装 / 修复 apcupsd
4. 升级 apcupsd
5. 管理监控服务
6. 查看日志与诊断
7. 更新管理工具
8. 卸载并恢复原状态
0. 退出
```

关机设置菜单直接显示当前参数，每项修改后自动保存，没有统一保存按钮：

```text
──────── UPS 关机设置 ────────

1. 停电多久后关机？           30 分钟
2. 电量低于多少时关机？       5 %
3. 剩余续航少于多久时关机？   3 分钟
4. 开机自动监控 UPS           开启
5. 备份 / 恢复配置

0. 返回
```

等待选择时约每 2 秒更新显示，输入参数时暂停重绘。设置旁优先显示服务实际运行值；无法取得时明确标记配置值。未安装、服务停止、UPS 未提供字段或通信中断时，会显示对应状态，不把缺失读数当成零。菜单、提示、状态解释和诊断摘要使用中文；命令、配置键名、设备型号和原始系统日志保留原文。

详细状态页补充设备序列号、输入输出电压、频率、温度和电池日期等读数，仅显示或解释设备实际提供的数据。

## 部署和卸载

支持范围为 PVE 8 / Debian 12、PVE 9 / Debian 13。安装脚本先检查实际系统和必要工具，再从当前已有 Debian 软件源安装 `apcupsd`，保留 PVE 软件源设置。已有软件源需要能正常更新，网络或订阅源问题会报告具体失败原因。

GitHub 部署入口是 `bootstrap.sh`。默认先把 `main` 解析为确切提交，再下载对应安装包，也可通过 `--ref` 指定完整提交号。一键部署命令为：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash -s -- --ref main
```

需要恢复自定义参数时，通过 `--config PATH` 读取之前导出的配置。具体操作见[部署与卸载](docs/部署与卸载.md)。

使用本地源码或 tar 源码包时，在项目根目录执行：

```sh
bash bin/pve-ups install
```

本地卸载命令不依赖 GitHub 连通：

```sh
pve-ups uninstall
```

非交互卸载：

```sh
pve-ups uninstall --yes
```

卸载按照首次安装前的记录撤销项目改动。原来没有 `apcupsd` 时，移除项目新增的软件及仍独占的新增依赖；原来已有 `apcupsd` 时，保留软件并恢复原配置与服务状态。系统日志、被其他软件使用的依赖保留。升级后的软件不承诺降回原来的版本。

## 命令行入口

以下命令以管理员身份运行。`set` 使用原生参数的单位，交互菜单则把停电等待转换为分钟。

| 命令 | 用途 |
| --- | --- |
| `pve-ups` 或 `pve-ups menu` | 打开中文菜单 |
| `pve-ups status` | 查看 UPS 状态和关机计时 |
| `pve-ups install` | 安装或修复，保留已设置的参数 |
| `pve-ups install --config PATH` | 安装并使用指定配置 |
| `pve-ups set TIMEOUT 1800` | 停电等待 1800 秒 |
| `pve-ups set BATTERYLEVEL 5` | 电量保护阈值 5% |
| `pve-ups set MINUTES 3` | 剩余续航保护阈值 3 分钟 |
| `pve-ups upgrade` | 升级 `apcupsd`，保留配置 |
| `pve-ups service start` | 启动监控 |
| `pve-ups service stop` | 停止监控 |
| `pve-ups service restart` | 重启监控 |
| `pve-ups service enable` | 启用开机监控 |
| `pve-ups service disable` | 关闭开机监控 |
| `pve-ups export PATH` | 导出可移植配置，目标文件必须不存在 |
| `pve-ups import PATH` | 导入并应用配置 |
| `pve-ups diagnose` | 查看诊断和相关日志 |
| `pve-ups tool-update REF` | 从指定分支、标签或完整提交更新管理工具 |
| `pve-ups uninstall` | 卸载或恢复安装前状态 |
| `pve-ups help` | 查看中文帮助 |

## 宿主机改动范围

| 位置 | 用途 |
| --- | --- |
| 发行版 `apcupsd` 软件包及必要依赖 | UPS 监控和关机 |
| `/etc/apcupsd` 等软件包配置位置 | USB 连接与关机参数，以实际软件包布局为准 |
| 原生 `apcupsd` 服务的启用状态 | 开机启动监控 |
| `/opt/pve-ups` | 管理工具文件 |
| `/usr/local/sbin/pve-ups` | 本地命令入口 |
| `/var/lib/pve-ups` | 首次基线、资源记录和恢复资料 |
| `/run/lock/pve-ups.lock` | 维护操作互斥锁，运行时文件由系统重启清理 |

部署、升级及卸载期间，临时使用 `/usr/sbin/policy-rc.d` 拦截通过 `invoke-rc.d` 发起的 `apcupsd` 自动启停，完成或失败后恢复原文件及属性；已有其他服务策略继续沿用。软件包维护脚本直接停止服务时不受这一策略约束，升级仍可能短暂中断监控。

复用系统正常关机流程；发行版的末期 UPS 断电集成需要在目标系统上检查。仅管理菜单时不需要额外后台服务。

## 运行隔离测试

在项目根目录执行，需要 Python 3：

```sh
bash tests/run.sh
```

测试使用临时目录和系统命令替身，不安装真实软件包、不修改真实服务。覆盖计时状态、来电取消展示、再次停电重新计时、参数校验与回滚、停电期间维护保护、软件安装升级卸载、原配置和服务状态恢复，以及终端菜单输入与退出。测试数量和结果以执行输出为准。

真实 UPS 事件、PVE 停机顺序和 UPS 输出断电仍需按硬件验收说明测试。
