# PVE UPS 管理

用于单台家用 PVE 8 / 9，APC UPS 通过 USB 连接，型号需兼容 `apcupsd`。提供中文菜单，安装、配置和管理系统原生 `apcupsd`；关闭菜单后，监控仍继续运行。

## 一键安装

在 PVE 上用 root 执行：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash
```

使用已有 Debian 软件源安装，不修改 PVE 软件源。安装前记录原配置和服务状态；重复安装保留已设置的参数。

## 中文菜单

```sh
pve-ups
```

菜单顶部显示 UPS 供电、电量、续航和关机倒计时。主菜单、详细状态和关机设置每 5 秒读取并原位更新，保留正在输入的菜单数字；空回车也可手动刷新。输入具体参数或执行维护时暂停刷新。设备读数保留全部项目：暂未上报或为 `N/A` 时值留空，上报后显示当前数值和单位，不沿用旧读数。

```text
1. 查看 UPS 详细状态
2. 查看停电与供电记录
3. 修改关机设置
4. 安装 / 修复 apcupsd
5. 升级 apcupsd
6. 管理监控服务
7. 查看事件记录与诊断
8. 更新管理工具
9. 卸载并恢复原状态
0. 退出
```

关机设置中可直接修改停电等待、电量保护、续航保护及开机自动监控。每项修改后自动校验、保存和应用，旁边显示当前参数；监控停止时，修改在下次启动后生效。

只查看状态可运行 `pve-ups status`，查看全部电池供电事件可运行 `pve-ups history`（或菜单第 2 项）。历史菜单保留分页及每 5 秒刷新，显示转入电池总次数、累计已记录电池供电时长、当前进行中的事件及恢复时间未记录的事件。低电压切换不等于完全停电；原因保留中文解释和设备英文原文，缺少可靠证据时显示“原因未记录”。

历史功能使用系统 `python3` 的标准库，不安装第三方 Python 包。记录保存在 `/var/lib/pve-ups/history.db`，更新保留记录，卸载清除本工具历史。旧版 `history.tsv` 原样保留并兼容导入，不覆盖用户关机参数或首次安装基线。

## 事件捕获与历史边界

捕获 `apcupsd` 的 `powerout`、`mainsback`、`onbattery`、`offbattery` 事件，按事件发生时间记录转入电池和恢复市电。短暂切换无需等到延迟的 `onbattery` 才记录。历史在后台保存，不等待历史写入完成后才执行原生事件处理、用户自定义脚本或关机动作。

原生日志增量读取，以事件顺序和来源身份关联、去重，不按时间相近合并不同切换。同一秒的不同事件分别保留。设备快照仅在能够确认对应事件时补充原因；不能确认的显示“原因未记录”。跨来源无法唯一关联的证据保留为“待核查”，不重复计入已确认次数。

历史区分当前正在电池供电、已恢复市电及恢复时间未知。通信中断或状态查询失败时，不再确认事件仍在进行，也不编造恢复时间。原始证据可从菜单第 7 项诊断查看，或使用 `pve-ups history --json`：`rows` 为已确认记录，`pending` 为待核查记录，`proof` 为原始证据。

历史更新使用事务和文件锁，事件、日志读取位置及清空边界一起保存。数据没有变化时不改写数据库，菜单刷新不重复解析全部日志。旧版有效记录兼容导入，保留原数据。

清空以发起请求的时刻为边界，移除此前的可见记录，保留去重依据和日志读取位置，防止旧日志重新导入；能确认发生于清空后的新事件继续保存。清空所在秒的迟到日志若无法确定前后，标为“清空边界待核查”。清空不删除原生日志、旧 TSV 或正在使用的锁文件；失败会报错，不提示成功。

同步错误可在历史菜单和 `pve-ups diagnose` 中查看，并尝试保存到 `/var/lib/pve-ups/history-error.json` 或系统日志。历史故障不影响原生监控和 PVE 关机，故障恢复后可继续记录。

未产生原生事件的短暂波动、日志丢失和服务停止期间的切换，以及未成功写入任何来源的数据，无法保证事后恢复。缺少共同事件身份、时钟异常或日志被改写时，可能无法唯一关联记录，相关证据保留为待核查。只有秒级时间精度的切换，时长可能显示为 0 秒。

排查通信问题可运行 `pve-ups diagnose`。菜单和状态解释使用中文，读数单位采用 `V`、`Hz`、`°C`、`%`、`min`、`s`；设备型号及原始系统日志保留原文。停电、恢复市电及通信中断／恢复的常规提示不再广播到终端，从菜单第 7 项查看原生事件记录；已存在的自定义事件脚本保留。

## 停电处理

- 默认持续停电 **30 分钟**后启动 PVE 正常关机，由 PVE 停止虚拟机、容器及宿主机。
- 倒计时期间恢复市电，取消本次计时和尚未开始的关机；再次停电重新计时。
- 新安装的电池保护为 **电量 50% / 剩余续航 30 分钟**；已有 `apcupsd` 保留符合范围的原保护值。电池保护或 UPS 低电量信号可提前触发关机。
- 已经开始关机后，恢复市电仍继续完成停机。

30 分钟不是电池续航保证，应为 PVE 停机预留电量。监控运行时，停电或供电状态无法确认会阻止修改参数、升级、卸载和停止／重启监控，避免清空当前计时；查看状态和日志仍可使用。

修改参数、升级软件可能短暂中断监控，请在市电稳定时操作。应用失败会恢复旧配置文件；通信无法确认时不会再次重启，应查看诊断及菜单中的实际运行值。

重装 PVE 后，重新执行一键安装，再通过菜单修改参数即可。

## 更新和卸载

升级 `apcupsd` 用菜单第 5 项；更新管理工具用菜单第 8 项，或运行 `pve-ups tool-update`，自动获取最新版。更新工具保留关机参数、历史和首次安装记录。更新前退出其他已打开的旧版菜单，完成后重新运行 `pve-ups`。

旧版首次更新可执行：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash -s -- --tool-only
```

卸载用菜单第 9 项，或执行：

```sh
pve-ups uninstall --yes
```

卸载无需联网：首次安装前没有 `apcupsd`，移除本项目新增的软件、配置及仍独占的新增依赖；原来已有 `apcupsd`，保留软件并恢复原配置和服务状态。清理 `/opt/pve-ups`、`/usr/local/sbin/pve-ups` 和 `/var/lib/pve-ups`。

系统日志、APT 索引／缓存／历史、共享依赖保留，运行时锁文件随系统重启清理。软件升级后不降回旧版本。不要提前手动删除 `/var/lib/pve-ups`，否则会丢失恢复依据。

## 实机确认

安装后先确认 `pve-ups status` 显示市电供电、型号和参数正确，再短暂断开 UPS 的市电输入，检查倒计时及恢复市电后取消计时。最后在允许停止业务的时间验证自动关机、虚拟机和容器正常停止；UPS 输出断电及来电自动开机取决于设备与主机设置，需要实机确认。

本项目尚未完成真实 PVE 与 UPS 的断电验收。

## 隔离回归测试

开发验证需要 `python3`、`bash` 和 `shellcheck`，从仓库目录运行：

```sh
bash tests/run.sh /tmp/pve-ups-test-report.txt
```

测试在独立的 `/tmp` 模拟 PVE 中运行，软件包、服务和危险电源命令均使用替身。报告记录语法检查、ShellCheck 和完整回归的真实退出状态；任一项失败时测试命令返回非零。模拟通过不替代真实 UPS 验证：**未完成实机验收**。

回归覆盖四类原生事件、低电压和短暂切换、同秒多次切换、日志／设备时间偏差、后台乱序、重启／通信故障、未完成事件补齐、清空与写入并发、轮转／旧格式迁移、无变化不写盘、磁盘满／权限／损坏数据库／提交中断，以及默认参数、已有配置、首次安装、重复安装、工具更新、卸载基线和原生保护分支。`curl`、软件包和服务均使用替身，测试不联网，不操作真实 UPS，不执行宿主机关机。
