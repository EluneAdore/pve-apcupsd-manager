# PVE UPS 管理

用于单台家用 PVE 8 / 9，APC UPS 通过 USB 连接，型号需兼容 `apcupsd`。提供中文菜单，安装、配置和管理系统原生 `apcupsd`；关闭菜单后，监控仍继续运行。

## 一键安装

在 PVE 上用 root 执行：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash
```

使用已有 Debian 软件源安装，不修改 PVE 软件源。安装前记录原配置和服务状态；重复安装保留已设置的参数。

## 中文菜单

```sh
pve-ups
```

菜单顶部保留 UPS 供电、电量、续航、接入设备总负载估算功率和关机倒计时，下方直接显示 CPU、内存与实体磁盘温度。主菜单、详细状态和关机设置正常约 5 秒读取并原位更新，保留正在输入的菜单数字；空回车也可手动刷新。输入具体参数或执行维护时暂停刷新。设备读数保留全部项目：暂未上报或为 `N/A` 时值留空，上报后显示当前数值和单位，不沿用旧读数。

```text
1. 查看 UPS 详细状态
2. 查看停电与供电记录
3. 修改关机设置
4. 安装 / 修复 apcupsd
5. 升级 apcupsd
6. 管理监控服务
7. 查看事件记录与诊断
8. 更新管理工具
9. 卸载并恢复原状态
0. 退出
```

关机设置中可直接修改停电等待、电量保护、续航保护及开机自动监控。每项修改后自动校验、保存和应用，旁边显示当前参数；监控停止时，修改在下次启动后生效。

只查看状态可运行 `pve-ups status`，查看全部电池供电事件可运行 `pve-ups history`（或菜单第 2 项）。历史菜单保留分页及每 5 秒刷新，显示转入电池总次数、累计已记录电池供电时长、当前进行中的事件及恢复时间未记录的事件。低电压切换不等于完全停电；原因保留中文解释和设备英文原文，缺少可靠证据时显示“原因未记录”。

排查问题可运行 `pve-ups diagnose`，或从菜单第 7 项查看事件记录与诊断。

历史功能使用系统 `python3` 的标准库，不安装第三方 Python 包。记录保存在 `/var/lib/pve-ups/history.db`，更新保留记录，卸载清除本工具历史。旧版 `history.tsv` 原样保留并兼容导入，不覆盖用户关机参数或首次安装基线。

## 简洁硬件概览

主菜单直接显示 CPU 使用率、CPU 温度、Package 平均功耗、内存已用／总量／使用率及全部可见实体磁盘温度。一次性查询同一区域可运行：

```sh
pve-ups hardware
```

主菜单正常约 5 秒刷新，CPU 使用率与 Package 功耗共用约 1 秒窗口，硬件采集限时 2 秒，另留 0.1 秒强制结束时间。UPS 查询和历史同步保持原有流程；它们已耗时至少 2.5 秒时，硬件概览跳过时间差采样，改用 0.5 秒快速采集及 0.1 秒强制结束时间，不继续叠加完整窗口。原有同步等待和异常系统调度仍可能延长整帧，无法保证精确周期；一帧超过周期后再等 5 秒，避免高频重试。CPU 来自 `/proc/stat`、现有 CPU HWMON 和 powercap；温度优先 Tdie，只有 Tctl 时明确标记。内存按 `MemTotal - MemAvailable` 计算。多个 Package 分别显示，不相加或标作整机功耗。

实体磁盘每次刷新按 `/sys/block` 和真实设备拓扑重新发现，支持热插拔。排除分区、虚拟块设备和内核已绑定 VFIO 的设备；同一拓扑或可靠的内核 WWID 合并重复路径。显示实际型号与当前节点名，同型号磁盘仍可区分，节点名不作为跨重启固定 ID。NVMe 同控制器的多个命名空间合并为一个设备。

NVMe 温度只取同一设备现有 HWMON 的 Composite 通道；内核明确标为非旋转的盘可读取归属于该盘的已有 drivetemp，或明确标注磁盘温度的存储 HWMON 通道。没有接口、无法唯一关联或读取失败时显示“不可用”。机械盘、旋转类型未知及无法可靠确认介质的 USB 桥接盘不读取温度，即使已有 drivetemp 也保守降级：[内核 drivetemp 文档](https://www.kernel.org/doc/html/latest/hwmon/drivetemp.html)说明读取它可能重置部分 HDD 的休眠计时，不能认为 HWMON 读取必然无 I/O 或不影响休眠。不会加载驱动、安装软件、执行 SMART 工具、读取磁盘内容或查询文件系统空间。普通块设备仍被宿主机识别时，单凭 sysfs 无法判断所有 VM 分配方式；不绕过整控制器直通。

磁盘按当前设备信息稳定排序，按终端宽度自动排列，不固定数量或列数；宽度允许时 CPU 指标共享一行。高度不足时，完整快照写入终端滚动缓冲并标为“静态快照”，暂停自动采集和重绘；空回车重新采集，输入数字并回车仍可操作原菜单。放大窗口会重新排版，能够容纳时恢复约 5 秒刷新；磁盘减少后也可用空回车恢复。两种显示模式共用同一输入编辑，退格删除、Ctrl+U 清空，未按回车不会执行菜单操作。没有单独硬件页面或分页，也不保存硬件历史或持久缓存。

UPS 功率继续按当前快照的 `NOMPOWER × LOADPCT / 100` 估算，单位 `W`，反映 UPS 所带全部设备的输出负载；不能当作插座输入功率或单台 PVE 功耗。缺少有效字段或通信失败时显示无法估算，0% 提醒低负载精度有限。

## 停电处理

- 默认持续停电 **30 分钟**后启动 PVE 正常关机，由 PVE 停止虚拟机、容器及宿主机。
- 倒计时期间恢复市电，取消本次计时和尚未开始的关机；再次停电重新计时。
- 新安装的电池保护为 **电量 50% / 剩余续航 30 分钟**；已有 `apcupsd` 保留符合范围的原保护值。电池保护或 UPS 低电量信号可提前触发关机。
- 已经开始关机后，恢复市电仍继续完成停机。

30 分钟不是电池续航保证，应为 PVE 停机预留电量。监控运行时，停电或供电状态无法确认会阻止修改参数、升级、卸载和停止／重启监控，避免清空当前计时；查看状态和日志仍可使用。

修改参数、升级软件可能短暂中断监控，请在市电稳定时操作。应用失败会恢复旧配置文件；通信无法确认时不会再次重启，应查看诊断及菜单中的实际运行值。

重装 PVE 后，重新执行一键安装，再通过菜单修改参数即可。

## 更新和卸载

升级 `apcupsd` 用菜单第 5 项；更新管理工具用菜单第 8 项，或运行 `pve-ups tool-update`，自动获取最新版。更新工具保留关机参数、历史和首次安装记录。更新前退出其他已打开的旧版菜单，完成后重新运行 `pve-ups`。

旧版首次更新可执行：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash -s -- --tool-only
```

卸载用菜单第 9 项，或执行：

```sh
pve-ups uninstall --yes
```

卸载无需联网：首次安装前没有 `apcupsd`，移除本项目新增的软件、配置及仍独占的新增依赖；原来已有 `apcupsd`，保留软件并恢复原配置和服务状态。清理 `/opt/pve-ups`、`/usr/local/sbin/pve-ups` 和 `/var/lib/pve-ups`。

系统日志、APT 索引／缓存／历史、共享依赖保留，运行时锁文件随系统重启清理。软件升级后不降回旧版本。不要提前手动删除 `/var/lib/pve-ups`，否则会丢失恢复依据。
