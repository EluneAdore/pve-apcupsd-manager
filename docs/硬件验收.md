# 硬件验收

隔离环境测试能够验证参数校验、状态显示、菜单逻辑和资源恢复，不能代替目标 PVE、USB 设备和 UPS 上的实际行为验证。以下步骤应在已经部署的目标主机上完成；真实关机测试选择允许停止业务的时间进行。

在源码项目根目录运行隔离测试：

```sh
bash tests/run.sh
```

需要 Python 3，无需 root。测试在临时目录中替换软件包管理、电源查询和服务命令，覆盖计时状态、配置应用与回滚、维护保护、生命周期恢复及终端菜单输入退出；实际测试数量与通过结果以执行输出为准。

## 1. 安装和通信

```sh
pve-ups status
pve-ups diagnose
```

检查项：

- 型号与实物一致，供电状态为市电供电。
- 显示电量、预计续航及负载；设备不提供的字段明确显示未提供。
- 默认停电等待为 30 分钟，新安装的保护阈值为 5% / 3 分钟；已有安装显示保留后的实际值。
- 服务正在运行并启用开机启动。
- 目标系统版本在支持范围内，关机末期 UPS 断电集成已检查。

通信失败时应显示实际错误，不应显示“市电供电”或“倒计时未启动”掩盖未知状态。先确认 USB 线、设备连接、服务日志及是否有其他软件占用设备，再处理配置。

## 2. 修改参数和自动应用

在市电稳定且通信正常时，通过菜单修改停电等待时间。

- 新值通过校验后自动保存并应用，无需额外保存操作。
- 返回菜单后显示新值，重新进入菜单仍然一致。
- 输入文字、负数或超出允许范围的值时保留原设置，并显示中文原因。
- 输入回车取消修改时保留原值。
- 修改过程中不重绘输入行；等待选择时继续刷新状态。
- 应用后通信失败时，明确区分旧配置文件已恢复与实际运行参数是否确认；供电不明时不再次重启，诊断页能帮助核对。

完成后恢复所需运行值，默认等待时间为 30 分钟。

## 3. 停电、来电和再次停电

UPS 输出继续连接主机，短暂中断 UPS 的市电输入，并在保护条件触发前恢复供电。

预期结果：

1. 检测到电池供电后，菜单显示已停电时长和关机倒计时。
2. 倒计时期间恢复市电，供电状态回到市电，计时结束，主机继续运行。
3. 再次短暂中断市电，从完整设定时长重新计时。
4. 退出菜单不会停止 `apcupsd` 监控。

状态更新存在 UPS 和服务的轮询间隔，应以实际检测时间为准。若电量或续航保护先触发，关机会提前开始，不属于计时失效。

## 4. 停电期间操作保护

在确认 UPS 已转为电池供电后，尝试修改参数、导入配置、升级软件、停止或重启监控。

预期结果：这些操作被拒绝，提示市电恢复后再操作；监控继续运行，当前计时不因菜单操作重置。查询状态、查看日志和导出配置仍可使用。

在服务运行但通信未知的情况下，应有相同的修改保护，并明确指出无法确认供电状态。

上述保护只保证已检测到停电或通信未知时拒绝开始维护。升级会短暂中断监控，不能把这一保护当成维护过程中任意瞬间停电均无缝处理的保证。

## 5. 正常关机

在计划好的测试时间，于市电供电状态下将等待时间改短，随后中断 UPS 市电输入。为排除续航不够，应在开始前确认电量和实际续航。

预期结果：

- 连续停电达到测试等待时间，系统发起正常关机。
- PVE 按正常停止流程处理虚拟机和容器。
- 宿主机完成停机，没有在写盘或停止虚拟机期间提前被切断输出。
- 若关机已经开始，此时恢复市电仍继续停机。

测试完恢复实际运行参数。若还要使用 UPS 关机后切断输出、来电后恢复输出及主机自动启动，应单独记录型号支持情况、执行顺序和固件设置，并完成对应测试。

## 6. 导出、卸载和重新部署

卸载会停止本项目提供的监控功能，安排在市电稳定且允许维护的时间执行。

1. 导出配置到系统盘之外。
2. 记录当前参数，以及安装前是否已经存在 `apcupsd`。
3. 运行卸载，并检查软件、配置、服务状态和工具文件的实际结果。
4. 断开互联网后验证本地卸载不需要访问 GitHub；软件包清理按当前系统能力执行。
5. 重新部署并导入配置，确认参数和 UPS 通信恢复。

已有安装应恢复首次记录的配置和服务状态；全新安装应清理本项目新增资源。共享依赖和系统历史记录保留。卸载失败时保留可重试记录并显示未完成项，不能只显示成功。

额外确认：后来添加到 `/etc/apcupsd` 的非软件包文件在清除软件包后仍然存在，且内容及文件属性保持。
