# 部署与卸载

## 首次部署

目标系统为单台 PVE 8 / Debian 12 或 PVE 9 / Debian 13，APC UPS 通过 USB 连接，型号已经确认兼容 `apcupsd`。以管理员身份执行安装，软件来自系统当前配置的 Debian 软件源。

当前软件源需要可正常更新。若家用系统的订阅源或网络导致更新失败，安装会报告原始失败原因，需要先处理已有软件源访问问题；工具不会自动替换 PVE 软件源。

项目提供 `v0.1.0` 源码，当前发布入口为 [GitHub 仓库](https://github.com/EluneAdore/pve-apcupsd-manager)的 `main` 分支。也可以使用本地 tar 源码包；需要固定版本时，指定完整提交号。

仓库内的 `bootstrap.sh` 负责先将指定引用解析为确切提交，下载相应版本，再进入本地安装流程。默认引用为 `main`；通过 `--ref REF` 可以指定分支、标签或完整提交号。

GitHub 一键部署命令：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash -s -- --ref main
```

固定版本时，将执行参数中的 `main` 替换为完整提交号。若要同时固定入口脚本自身的版本，还应把下载地址中的 `main` 替换为相同提交号。脚本也支持已经存在的标签引用。

使用本地源码时，从项目根目录部署；tar 源码包先解压，再进入包内项目根目录运行相同命令：

```sh
bash bin/pve-ups install
```

本地管理入口准备好后，执行：

```sh
pve-ups install
```

安装流程包括检查系统、记录首次基线、安装必要软件、配置 USB 监控、设置关机条件、启用服务和检查通信。可重复运行安装；正常情况下复用项目记录，保留你已经设置的参数。

全新部署的默认值为：

```text
停电等待：30 分钟
电量保护：5 %
续航保护：3 分钟
开机监控：开启
```

已有 `apcupsd` 时，安装前备份配置及服务状态，保留符合校验范围的电量和续航保护阈值。不能读取或验证原配置时，报告具体问题，避免直接覆盖。

安装失败时，会尝试撤销本次已经完成的改动并给出失败位置。若恢复失败，应根据提示处理并重新运行，不能把部分恢复当成卸载成功。

若服务已经启动但 UPS 通信尚未确认，会明确报告验证失败并保留恢复资料和本地管理入口。供电状态未知时不强行停掉监控进行清理，应先检查 USB 连接和详细状态，待市电及通信恢复后处理。

## 修改和查看

```sh
pve-ups
pve-ups status
pve-ups diagnose
```

菜单中的每项参数提交后立即校验、保存和应用。输入无效时保留原值；应用失败时恢复旧配置文件，并报告具体原因。监控服务停止时，只保存配置，在下次启动时生效，并明确提示这一状态。

如果应用后通信失败，旧文件恢复不等于服务已经重新加载旧参数。供电状态无法确认时，工具不会为了回滚再次重启，以免重置新发生的停电计时。此时查看 `pve-ups diagnose` 和设置菜单，核对标记为运行值的实际参数；市电及通信恢复后再修复。

电池供电或运行中的服务无法确认供电状态时，修改参数、导入配置、软件升级和停止、重启监控会被阻止，以免清空尚在运行的停电计时。服务停止或尚未安装时，状态页会明确显示监控没有运行。

命令行示例：

```sh
pve-ups set TIMEOUT 1800
pve-ups set BATTERYLEVEL 5
pve-ups set MINUTES 3
```

`TIMEOUT` 的单位是秒；交互菜单中的对应输入单位是分钟。`TIMEOUT 0` 禁用等待时间条件，其他电池保护条件仍然有效。

## 重装 PVE 后恢复

调整参数后，在关机设置菜单第 5 项选择备份，或导出配置到系统盘之外：

```sh
pve-ups export /mnt/backup/pve-ups.conf
```

重装系统后，可用以下一条命令下载部署并读取配置：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash -s -- --ref main --config /mnt/backup/pve-ups.conf
```

在管理入口已经部署好的系统上，也可以执行：

```sh
pve-ups install --config /mnt/backup/pve-ups.conf
```

随后检查 UPS 通信和参数是否与备份一致。新系统的安装基线应重新建立；原系统的 `/var/lib/pve-ups` 是旧系统的卸载恢复记录，不应直接当作新系统基线恢复。

已经安装时可通过关机设置菜单第 5 项恢复，或执行：

```sh
pve-ups import /mnt/backup/pve-ups.conf
```

配置导入检查本机 USB 模式及必要的关机参数，不把配置文件作为脚本执行。使用本工具导出的配置进行恢复；其中的事件脚本和断电标记目录需符合本机方案。导入与手动修改遵循相同校验、供电状态检查和应用恢复规则。

## 软件与管理工具升级

升级 `apcupsd`：

```sh
pve-ups upgrade
```

升级使用现有软件源中适用于当前发行版的版本，并保留项目配置。刷新索引后显示当前版本及软件源候选版本，再次确认供电后执行升级。升级失败时报告实际结果；软件包升级不承诺自动降回旧版本。

升级存在短暂监控中断，只允许在已确认市电时开始。临时 `policy-rc.d` 能拦截通过 `invoke-rc.d` 发起的自动启停，但不能阻止软件包维护脚本直接停止服务。工具保留发行版原生维护脚本，不保证维护瞬间新发生的停电能够无缝监控；建议在供电稳定的维护时段升级。

更新管理工具：

```sh
pve-ups tool-update REF
```

`REF` 为分支、已发布标签或完整提交号，会先解析为确切提交再下载。工具更新和 `apcupsd` 软件包升级是两项独立操作。首次安装前的恢复基线在工具更新后继续保留。

从菜单更新管理工具后，退出当前菜单，再运行 `pve-ups` 载入新版本。

也可从下载入口仅更新管理工具：

```sh
curl -fsSL https://raw.githubusercontent.com/EluneAdore/pve-apcupsd-manager/main/bootstrap.sh | bash -s -- --ref REF --tool-only
```

这要求入口脚本已经下载，并且本机已有本项目的管理记录。

## 本地卸载

卸载使用本地安装记录，无需访问 GitHub：

```sh
pve-ups uninstall
```

非交互方式：

```sh
pve-ups uninstall --yes
```

卸载按首次安装前的状态处理：

| 首次安装前状态 | 卸载行为 |
| --- | --- |
| 没有 `apcupsd` | 停止监控，移除项目新增的软件和配置，清理仍独占的新增依赖 |
| 已有 `apcupsd` | 保留软件，恢复原配置的内容与属性，恢复原服务启用及运行状态 |
| 存在共享依赖 | 保留被其他软件使用的包 |
| 项目新增文件 | 清理管理工具、入口和完成恢复后不再需要的记录 |

软件包清除可能删除整个配置目录。卸载前保留目录中不属于软件包的用户文件，清除后恢复这些文件，避免牵连后续加入的配置资料。

每次卸载结果均以实际执行情况为准。中断或失败后可以再次运行，已完成的部分不会重复破坏其他设置。不要提前手动删除 `/var/lib/pve-ups`，否则可能丢失原配置及资源归属信息。

这里的“完整卸载”指完整撤销项目负责的功能和配置改动。系统日志、软件包管理历史和共享资源保留，`/run/lock/pve-ups.lock` 为运行时锁文件，由系统重启清理；如果升级后的旧软件版本已不在仓库，无法承诺恢复原二进制版本。后续手工变更导致无法判断资源归属时，应报告冲突，而不是盲目清理。

## 关机和 UPS 输出断电

`apcupsd` 达到关机条件后调用系统正常关机，PVE 按自身流程停止虚拟机、容器及宿主机。等待过程中恢复市电会取消尚未开始的关机；已经开始停机则继续完成。

UPS 输出断电属于关机末期的另一个环节。应检查目标发行版软件包提供的集成是否存在、是否按预期执行，以及 UPS 型号是否支持。不要仅凭服务运行或状态查询成功，就认定这一环节已验证。

来电自动开机还取决于 UPS 输出恢复及主机固件设置，需要在实机上单独验收。
